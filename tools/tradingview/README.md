# TradingView：無遮蔽原則＋PVT 通道＋均線

| 檔案 | 說明 |
|---|---|
| `unshielded_pvt.pine` | Pine Script v6 指標（overlay），把三組東西畫在同一張圖 |
| `verify_unshielded_pvt.py` | 用 Python 模擬 Pine 的逐根語意，和本專案 Python 版逐根比對 |

## 用法

1. TradingView → Pine 編輯器 → 貼上 `unshielded_pvt.pine` → 加到圖表。
2. 建議用**日內 K 線**（1 分、5 分……）。兩個邏輯都以「交易日」為單位重設或分段，日線以上的週期沒有意義。
3. 警示：「建立警示」→ 條件選本指標 →「無遮蔽多單」或「無遮蔽空單」。建議頻率選 **Once Per Bar Close**，
   因為即時 K 棒還沒收完時，訊號會隨價格出現又消失（收完才定案，歷史 K 棒不會重畫）。
4. 驗證（不需要 TradingView）：

   ```bash
   uv run python tools/tradingview/verify_unshielded_pvt.py
   ```

## 與原始邏輯的對應

### 無遮蔽（`methods/期貨奇績1/wang_unshielded.afl` WANG 段、`wang_unshielded.py` 的 `wang_afl()`）

- AFL 的 `for` 迴圈一次處理一根，Pine 每根執行一次；狀態 `hh/hl/lineS/lh/ll/lineL/resetFlag` 用 `var` 保存，
  變數名稱和 Python 移植版相同，分支順序一行對一行。
- 每根流程：重設（換日或上一根 `resetFlag`）→ 否則依序更新最高 K（含同高取低點較高）→ 最低 K（含同低取高點較低）
  → 空單四條件（成立：最低 K 設成本根、`resetFlag`；否則線下移）→ 多單四條件（鏡像）。
- `resetFlag` 在訊號根設為 true，**下一根**執行時才進入重設分支，和 AFL 迴圈下一輪相同；重設根不判斷訊號。
- 畫出的無遮蔽線是**條件①比較當下**的值（最高／最低 K 更新後、本根低／高點納入前），重設根是 `na`（斷線）。
  這和 `wang_afl()` 的追蹤欄位 `line_s/line_l` 相同，也就是解說文件圖上的藍線、橙線。
- AFL 的 ALMA 不參與訊號，沒有移植；`*_index`、`debug*`、`during_*` 沒有作用，也沒有移植。

### PVT 通道（`q2-03-01-PVT通道N型訊號.md` §3.1、`q2_03_01_pvt_n_type.py`）

採用的定義：**通道＝兩條趨勢階梯**，只移植 `on_bar` 的步驟 1（更新階梯）與步驟 2（控盤易主），不移植 N 型結構、過濾、進出場。

- 轉折點：每個交易日各自計算（`_pivots_by_session`）；同值平台與「變形」（夾一根較差 K）照 `_groups` 由左而右貪婪分組，
  最多 4 根（`_MAX_PLATEAU`）；組值要嚴格優於左側（同日內）與右側各 `level` 根；**在第 e+level 根確認**
  （`_Pivot.confirm`），Pine 同樣延遲，不偷看。Pine 版把 `_groups` 改成逐根增量：需要的 K 棒還沒出現時先不定案。
- 下緣（多趨勢階梯）：新確認谷點和「上一個被採用的谷點」比，差距 > 忽略值時取孰低；上緣（空趨勢階梯）用峰點取孰高（p.95–96）。
  同一根先處理谷點再處理峰點（同 Python）。
- 控盤易主（p.97）：收盤 > 上緣 → 多方；收盤 < 下緣 → 空方；易主當根用最近兩個已確認谷（峰）點孰低（孰高）重建下緣（上緣）（`_reseed`）。
  冷啟動（尚無方向）時，率先被突破／跌破的任一條階梯決定初始方向（Python 的詮釋，照搬）。
- 階梯和控盤方向跨交易日延續（p.101），只有轉折點分日計算。
- 畫出的是每根**處理完**的階梯值（下一根要比較的值）；易主當根，被重建的那一條會在當根跳動。
- 背景色依據：書中 p.94、p.97 明確定義「收盤突破多趨勢階梯＝空轉多控盤、跌破＝轉空方控盤」（文件 §1、§3.1），
  對應 Python 的 `st["regime"]`。

### 均線

直接用 Pine 內建函式，本專案沒有對應的 Python 實作，未驗證。

## 驗證結果

`verify_unshielded_pvt.py` 用 `data/tx_day_5min.parquet`、`data/tx_day_1min.parquet` 全期資料（2024-05-09～2026-09-24）：

| 項目 | 結果 |
|---|---|
| 無遮蔽 5 分（兩種換日判斷） | 參考 3,050 個訊號，模擬命中 3,050（100%），多出 0；兩條無遮蔽線逐根 100% 相同 |
| 無遮蔽 1 分（兩種換日判斷） | 參考 16,777 個訊號，100% 相同，多出 0 |
| 無遮蔽「修正初值」 | 只少掉資料第一天的假多單（5 分 2024-05-09 09:10、1 分 08:47），其餘相同，符合解說文件 5.7 |
| PVT 5 分 level 2／4、1 分 level 2 | 轉折點確認位置與價格完全相同；上緣、下緣、控盤方向逐根 100% 相同 |

注意：驗證的是「Pine 語意的 Python 模擬」，不是 TradingView 實際執行結果（見下方沒把握的地方）。

## 已知差異

1. **換日判斷**：AFL 用 `TimeNum[i-1] > TimeNum[i]`；Pine 預設用 `timeframe.change("D")`。日盤資料上兩者相同（已驗證）。
   含夜盤時，AFL 會在**午夜**重設，Pine 會在 TradingView 定義的交易日起點重設（台指期通常是 15:00 夜盤開盤）。
   想完全照 AFL，可選「AFL 原樣：TimeNum 倒退」。
2. **PVT 的分日**：Python 以**日曆日期**分 session；Pine 用同一個換日判斷。日盤資料相同；夜盤資料會不同。
3. **圖表起點**：Python 從資料第一根算起；TradingView 的第一根是圖表載入的第一根（常在某日中間），
   所以起點附近的無遮蔽狀態、第一天的轉折點、冷啟動方向會和從完整資料算的結果不同，往後自然收斂。
4. **疑點切換**：「修正初值 0 疑點」預設關閉，照原樣從 bar_index 2 起算、狀態初值 0，圖表起點可能出現假多單（解說文件 5.1、5.7）。
   開啟後從第 1 根起算，並把第 1 根當重設根。其他疑點（重設根不判斷、並列時線往上重設、十字 K 不出訊號等）屬於 AFL 的行為本身，照原樣保留。
5. **轉折點層級最小 2**：Python 在 level 1 時判斷平台是否結束要看到 e+2，會比確認時點多看一根；Pine 不開放 level 1。
6. 價格比較用 TradingView 的原始報價（`high == hh` 等相等判斷），與 Python 的浮點比較相同前提是報價都在跳動點上。

## 沒把握的地方

- **沒有在 TradingView 上編譯執行過**。語法依 v6 規則自行檢查（`var` 初始化、`na` 以 `na()` 判斷、`plot` 只在全域、
  `ta.*`／`timeframe.change` 每根在全域呼叫、`for` 迴圈下界大於上界時先擋掉），仍可能有編譯器才抓得到的問題。
- `timeframe.change("D")` 與 `session.isfirstbar` 在 TAIFEX 商品（例如 `TXF1!`）上的交易日切點，以及夜盤是否算入同一交易日，未實測。
- 即時 K 棒上 `var` 陣列（PVT 的當日高低點陣列、待確認分組）的 rollback 行為：依 Pine 文件應與一般 `var` 變數相同，未實測。
- 均線週期在不同 K 線週期的意義，以及 LSMA／HMA 的參數是否與使用者原本的設定一致，沒有來源可核對。
- PVT 冷啟動方向、`_groups` 最多 4 根的平台上限，本來就是 Python 版的詮釋（見方法文件），Pine 只是照搬。
